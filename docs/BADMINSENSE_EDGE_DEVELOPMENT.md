## 1. 项目概述

BadminSense-Edge 是一款运行于 openvela 智能手表的羽毛球运动监测应用。应用利用腕部六轴 IMU 捕获挥拍动作，在设备端完成特征提取和击球分类，同时结合心率、运动时长和移动数据生成训练记录。

项目强调三项比赛价值：

1. **真实硬件能力**：接入加速度计、陀螺仪和可用的健康传感器。
2. **端侧实时计算**：在手表上完成挥拍检测和击球分类，不依赖网络推理。
3. **完整产品闭环**：覆盖开始运动、实时反馈、运动总结、历史复盘和参数设置。

### 1.1 目标用户

- 希望量化日常训练的羽毛球爱好者；
- 需要观察击球结构、运动强度和训练趋势的进阶玩家；
- 希望使用轻量穿戴设备记录训练、无需携带手机的用户。

### 1.2 核心指标

| 指标 | 目标值 | 验证方式 |
| --- | --- | --- |
| IMU 采样频率 | 稳定达到 50 Hz | 统计连续采样时间戳 |
| 挥拍检测延迟 | 小于 100 ms | 事件时间戳与峰值时间戳对比 |
| 挥拍计数召回率 | 大于等于 85%（目标） | 标注测试集评估 |
| 击球分类准确率 | 大于等于 70%（目标） | 混淆矩阵和人工标注对比 |
| 连续挥拍重复计数率 | 小于等于 5%（目标） | 连续动作测试 |
| 应用启动时间 | 小于 2 s | 真机重复测量 |
| 运动记录 | 异常退出时可恢复 | 中断恢复测试 |

> 准确率指标必须以真机采集和人工标注结果为准；文档和演示中不得把模拟数据描述为真实测量结果。

## 2. 产品范围

### 2.1 本期必须完成（P0）

- 七页面完整导航和圆屏交互；
- 运动开始、暂停、恢复、结束、保存和放弃；

- 实时展示运动时长、心率、卡路里和击球统计；
- 运动记录本地保存、历史列表和详情查看；
- 传感器不可用时明确降级，不阻塞其余功能；
- 模拟器 Mock 模式与真机模式有清晰标识；
- 可复现的构建、安装、测试和演示说明。

- 步数、距离、平均速度与最高速度；

- GPS 轨迹地图；
- 端侧神经网络训练；
- 医疗诊断或健康风险结论。

## 3. 统一术语与分类口径

产品采用五种羽毛球击球类型，页面、算法、存储和文档必须使用相同字段：

| 字段 | 中文名称 | 典型特征（初始假设） |
| --- | --- | --- |
| `highClear` | 高远球 | 向上挥动明显，角速度较高，轨迹较完整 |
| `smash` | 杀球 | 加速度和角速度峰值高，向下分量明显 |
| `drive` | 平抽 | 水平方向占主导，持续时间较短 |
| `lift` | 挑球 | 自下向上，峰值中等，抬升特征明显 |
| `drop` | 吊球 | 动作较柔和，能量和峰值相对较低 |

“正手/反手”属于挥拍手型或方向属性，不作为五分类结果。后续如能稳定识别，可作为 `handedness` 附加字段保存。

| ID | 页面 | 路径 | 优先级 | 主要职责 |
| --- | --- | --- | --- | --- |
| P001 | 主页 | `pages/index` | P0 | 开始运动、历史、设置、最近训练摘要 |
| P002 | 设置页 | `pages/settings` | P0 | 单位、体重、惯用手、灵敏度、心率预警、Mock 模式 |
| P003 | 运动概览 | `pages/workout/overview` | P0 | 时长、心率、卡路里、运动状态和控制 |
| P004 | 击球记录 | `pages/workout/hits` | P0 | 总次数、最新击球、五类统计和置信度 |
| P005 | 移动记录 | `pages/workout/movement` | P1 | 步数、距离、均速和最高速度 |
| P006 | 运动总结 | `pages/workout/summary` | P0 | 本次训练汇总、保存或放弃；历史查看时只读 |

### 4.1 导航规则

```text
主页 ──> 设置
 │
 ├────> 历史 ──> 运动总结（只读详情）
 │
 └────> 运动概览 <──滑动──> 击球记录 <──滑动──> 移动记录
                         │
                         └──任一运动页结束──> 运动总结──>主页
```

运动中的三个页面应共享同一运动会话，切页不得重建计时器或传感器订阅。实现上可使用一个 `swiper` 容器承载三个视图，也可使用三个路由页面，但状态只能由单一会话控制器维护。

### 4.2 页面详细需求

#### P001 主页

- 显示应用标识、设备/传感器就绪状态和最近一次训练摘要；
- “开始运动”为主操作；传感器异常时允许进入降级模式并给出提示；
- 提供历史记录与设置入口；
- 检测到未完成会话时提供“继续”或“放弃”。

#### P002 设置页

- 单位制：公制/英制；
- 体重：用于卡路里估算，需限制合理范围；
- 惯用手：左手/右手；
- 检测灵敏度：低/中/高，映射至算法阈值；
- 心率预警：开关和阈值；
- Mock 模式：仅供模拟器和演示，UI 必须持续显示“模拟数据”；
- 修改后即时保存，非法值不写入存储。

#### P003 运动概览

- 展示运动状态、时长、当前心率和卡路里；
- 暂停后停止累计有效运动时间，不再计入挥拍事件；
- 结束操作需要防误触确认；
- 心率缺失显示 `--`，不得伪造随机值；
- 显示三个运动页的位置指示器。

#### P004 击球记录

- 展示击球总数、最新击球类型、最新置信度；
- 展示五种类型计数；
- 可显示最近若干次击球事件；
- 真机模式禁止使用手动随机计数；开发调试按钮只能在明确的 Mock 模式出现。

#### P005 移动记录

- 展示步数、距离、平均速度和最高速度；
- 若设备无可用步数/速度来源，显示“不支持”或简化为步数，不能生成随机业务数据；
- 明确数据来源和估算方法。

#### P006 运动总结

- 展示日期、有效时长、卡路里、心率统计、击球总数和五类分布；
- 新结束会话显示“保存/放弃”；
- 从历史页进入时为只读详情，显示“返回”，不得再次保存同一记录；
- 保存成功后更新历史和最近训练；保存失败时保留当前数据并提示。

#### P007 历史记录

- 按开始时间倒序；列表展示日期、时长、卡路里和击球总数；
- 点击进入只读总结；
- 支持空状态；
- 单条损坏记录应跳过或提示，不得导致页面整体崩溃。

## 5. 核心用户流程

### 5.1 正常训练

1. 用户在主页开始运动；
2. 应用创建会话并初始化传感器；
3. 运动页实时刷新健康、击球和移动数据；
4. 用户可暂停/恢复并滑动查看三个视图；
5. 用户结束运动，进入总结页；
6. 用户保存记录，历史列表和最近训练同步更新。

### 5.2 传感器降级

1. 初始化时检测每个传感器是否可用；
2. 单个传感器失败只关闭依赖功能；
3. UI 显示具体状态，例如“心率不可用”“IMU 不可用”；
4. IMU 不可用时不产生击球分类结果；
5. 错误写入调试日志，不包含个人敏感信息。

### 5.3 意外中断恢复

- 运动中每隔固定周期保存轻量会话快照；
- 应用重新启动时检测 `active_workout`；
- 用户选择继续时恢复时长和累计统计并重新订阅传感器；
- 用户选择放弃时删除快照。

## 7. 传感器与算法设计

### 7.1 IMU 数据模型

```javascript
{
  timestamp: 0,
  accel: { x: 0, y: 0, z: 0 },
  gyro: { x: 0, y: 0, z: 0 },
  accelMagnitude: 0,
  gyroMagnitude: 0
}
```

- 目标采样率为 50 Hz，期望周期约 20 ms；
- 加速度计和陀螺仪按最近时间戳配对，记录时间差；
- 缓冲区建议保留最近 2～3 秒；
- 启动后先采集静止窗口估算零偏；
- 滤波参数必须集中配置，不散落在页面代码中。

### 7.2 挥拍检测状态机

```text
IDLE ──超过启动阈值──> CANDIDATE ──持续满足──> ACTIVE
 ↑                         │                     │
 └──候选超时/噪声─────────┘                     └──低于结束阈值──> COOLDOWN ──> IDLE
```

- 结合加速度模长和角速度模长，避免单传感器误触发；
- 合理挥拍窗口初始范围为 80～400 ms，需用真机数据修订；
- 冷却时间用于连续挥拍去重；
- 过长、过短、数值异常的窗口直接丢弃并记录原因；
- 阈值参考 `docs/IMU_THRESHOLD_REFERENCE.md`，最终值以 50 Hz 真机数据标定。

### 7.3 特征集合

- 加速度：三轴及模长的峰值、均值、标准差、极差、斜率、峰值时刻；
- 角速度：三轴及模长的峰值、均值、标准差、极差、斜率；
- 时间：持续时间、上升时间、下降时间；
- 方向：主导轴、上下/水平趋势；
- 能量：窗口内平方和或积分近似；
- 融合：加速度峰值与角速度峰值的时间差。

### 7.4 分类器

第一版使用可解释的规则/加权评分分类器：

1. 对特征归一化；
2. 为五类计算匹配分数；
3. 最高分为预测类型；
4. 根据最高分、次高分差值计算置信度；
5. 低于最低置信度时标记为 `unknown`，不强制归入五类；
6. 使用短时序规则抑制不合理的重复事件。

规则、阈值和版本号应随记录保存，便于复现实验。

### 7.5 数据采集与调优

- 至少覆盖不同选手、左右手和不同强度；
- 每种击球建议采集不少于 50 次有效样本作为初始验证集；
- 保存原始或降采样后的 IMU 窗口、人工标签和预测结果；
- 训练/调参数据与最终评测数据分离；
- 输出混淆矩阵、准确率、召回率和误计数统计；
- README 中披露测试规模和限制。

## 8. 健康与运动数据

### 8.1 心率

- 以目标 openvela 固件实际提供的 API 为准，开发前制作最小 API 探针验证；
- 保存当前、平均和最大心率；
- 过滤明显越界值，短时缺失保留最近有效值并标记时间；
- 长时间缺失显示 `--`；
- 心率预警只作为运动提示，不提供医疗建议。

### 8.2 卡路里

- 优先采用设备健康服务提供的累计值；
- 若系统无直接数据，则基于体重、运动时长和强度等级进行透明估算；
- 算法说明和单位写入文档；
- 暂停时间不计入有效运动消耗。

### 8.3 移动数据

- 优先使用系统步数或运动服务；
- 距离可由步数和用户步幅估算，并标注为估算值；
- 无可靠数据源时显示不支持，不能用随机数替代真实数据。

## 9. 数据模型与存储

```javascript
{
  schemaVersion: 1,
  id: 'workout_<timestamp>',
  startTime: 0,
  endTime: 0,
  duration: 0,
  activeDuration: 0,
  dataSource: 'device|mock',
  device: { model: '', platformVersion: '' },
  heartRate: { current: null, avg: null, max: null, sampleCount: 0 },
  calories: { value: 0, method: 'system|estimated' },
  hits: {
    total: 0,
    highClear: 0,
    smash: 0,
    drive: 0,
    lift: 0,
    drop: 0,
    unknown: 0
  },
  movement: { steps: null, distance: null, avgSpeed: null, maxSpeed: null },
  algorithm: { version: 'rule-v1', sensitivity: 'medium' }
}
```

存储键统一为：

| 键 | 内容 |
| --- | --- |
| `user_settings` | 用户设置 |
| `active_workout` | 未完成运动快照 |
| `workout_history` | 历史记录数组 |
| `last_workout` | 最近一次已保存记录摘要 |

所有读取都需要处理空值、旧版本和 JSON 损坏。历史记录设置合理上限，并在写入失败时保留当前会话。

## 10. UI 与交互规范

- 设计基准为 480 × 480 圆屏；关键内容位于中央安全区；
- 主操作最小可点击尺寸建议不低于 64 × 64 px；
- 运动中优先展示可一眼读取的大数字；
- 深色背景配高对比文字，状态不能只靠颜色表达；
- 结束、放弃、清除等操作需要确认或提供恢复路径；
- 列表和长内容使用圆屏可用的滚动容器；
- 页面样式避免使用目标运行时不支持的 Web CSS；
- 中文为默认语言，i18n 键保持完整，为英文版本预留。

## 11. 异常与安全要求

| 场景 | 处理 |
| --- | --- |
| IMU 初始化失败 | 禁用击球监测，展示明确提示，其余计时功能可用 |
| 心率不可用 | 显示 `--`，不阻塞训练 |
| 数据间隔异常 | 丢弃异常样本或重置当前候选窗口 |
| 存储失败 | 保留会话数据并允许重试，不假报成功 |
| 应用意外退出 | 周期性快照，重启后允许恢复 |
| Mock 模式 | 全程显著标识，记录中写入 `dataSource: mock` |
| 无效设置 | 使用默认值并拒绝写入越界数据 |

传感器和心率数据只保存在本地；默认不上传网络。日志不得记录完整原始健康数据或其他用户敏感信息，除非用于明确的测试数据集并获得授权。

## 12. 测试与验收

### 12.1 单元/模块测试

- 滤波器：固定输入、阶跃输入和异常值；
- 挥拍检测：正常窗口、边界时长、重复动作和噪声；
- 特征提取：空窗口、单样本和标准样本；
- 分类器：五类模板、低置信度和阈值边界；
- 存储：空数据、损坏 JSON、容量失败和版本迁移；
- 时长：暂停、恢复和异常退出恢复。

### 12.2 集成测试

- Mock 数据完整走通七页面和保存流程；
- 真机完成传感器订阅、运动会话和历史回放；
- 反复进入/退出运动页面后无重复订阅和计时器泄漏；
- 暂停时不新增挥拍和有效时长；
- 历史详情不会重复保存；
- 中文和英文资源均无缺失键。

### 12.3 真机验收场景

1. 静止佩戴 2 分钟，不应大量误计数；
2. 日常走动、抬腕和拍手，观察抗干扰能力；
3. 每种击球完成一组标注动作，统计分类结果；
4. 快速连续挥拍，检查漏计和重复计数；
5. 训练中暂停、切页、息屏/恢复和异常退出；
6. 保存后重启应用，历史记录仍可读取。

### 12.4 P0 完成定义

- 七页面均可在目标设备运行，主流程无阻断；
- 真机 IMU 数据驱动挥拍计数，不依赖随机数；
- 五类分类输出与存储字段一致；
- 所有传感器订阅和计时器在退出时释放；

## 15. 风险与待确认项

| 风险/待确认 | 影响 | 处理方案 |
| --- | --- | --- |
| 目标固件传感器 API 与示例不一致 | 无法获取 IMU/心率 | 先编写最小真机 API 探针，以设备实际接口为准 |
| 50 Hz 对快速挥拍分辨率有限 | 漏峰值、分类下降 | 使用窗口特征、插值/峰值保持，并用真机数据调参 |
| 腕部姿态和惯用手差异大 | 规则泛化不足 | 加入惯用手设置、方向归一化和多用户数据 |
| PPG 在剧烈运动中噪声较大 | 心率不稳定 | 合理过滤、显示有效性，不影响击球流程 |
| 圆屏空间有限 | 五类统计拥挤 | 分层信息、滑动页面和大数字优先 |
| 模拟数据与真实数据混淆 | 演示可信度受损 | 强制标识数据来源并随记录保存 |
